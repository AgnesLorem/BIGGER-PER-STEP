## Integration Boundary

- `ReplicatedStorage.BiggerShared.Game.Config.UpgradesConfig` defines the 8 upgrades, linear sequence, and unlock/multiplier helper rules.
- `LevelFormula.GetLevelFromBigger(Session.Bigger)` is the single canonical source of Level for unlock validation.
- `EquipmentService` registers in `GameBootstrap.luau` and manages server-side unlock/equip RPC calls and state push via `ReplicatedStorage.BiggerEvents.Equipment`.
- `GrowthFormula.GetMultiplier` reads `Session.EquippedGrowthUpgrade` via `UpgradesConfig.GetMultiplier` and computes `equipment × HasDoubleMultiplier × HasVip`.
- `SaveService:QueueProfileSave(Player)` provides non-blocking FIFO save queuing upon successful unlock or equip.
- `EquipmentController` manages client-side equipment state snapshot (`EquipmentState`) and RPC actions.

## Approved Equipment Model & Decisions

### 1. Equipment Sequence & Multipliers
- `None`: 1x (virtual default state)
- `Protein`: 1.5x (1 Destruction, Level 5)
- `SilverProtein`: 2x (5 Destruction, Level 10)
- `GoldProtein`: 3x (15 Destruction, Level 25)
- `DiamondProtein`: 5x (30 Destruction, Level 50)
- `GrowthSerum`: 10x (60 Destruction, Level 100)
- `AdvancedSerum`: 25x (120 Destruction, Level 200)
- `TitanSerum`: 50x (250 Destruction, Level 500)

### 2. `None` Semantics
- Virtual equipment state; `UnlockedGrowthUpgrades` does not store `None=true`.
- `EquippedGrowthUpgrade = nil` represents `None`.
- `None` is always available and cannot be unlocked or persisted as a string.
- `Protein` is the first real upgrade and has no persistent predecessor.

### 3. Level Authority
- Unlock validation MUST calculate Level using `LevelFormula.GetLevelFromBigger(Session.Bigger)`.
- Client `Player:GetAttribute("Level")` is for display only and must never be used for authorization.

### 4. Offline Progression & Save Isolation
- Equipment multipliers apply to active gameplay growth ONLY.
- Offline progression retains existing approved entitlement rules. `UpgradesConfig` is NOT imported by `SaveService`.

### 5. Immediate Non-Blocking Save
- Successful unlock or equip calls `SaveService:QueueProfileSave(Player)` to queue a save in the per-UserId FIFO worker without blocking the client remote invocation.
